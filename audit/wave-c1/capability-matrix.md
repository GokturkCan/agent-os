## Lifecycle vocabulary (an index entry or a file on disk is NOT proof of selection)

| State | Meaning | How it was established here |
|---|---|---|
| INSTALLED | files are on a host's loading path | filesystem check |
| DISCOVERABLE | the host lists name+description to the model | isolated `claude -p` probe: model listed the project skill |
| LOADABLE | the model can load it through the Skill tool | `Skill` tool_use observed in the stream log |
| POLICY-ELIGIBLE | Agent OS policy lets a dispatched worker use it | would need a registry record + worker exposure; **none of the candidates has one** |
| ACTUALLY USED | the model chose it in a task without being told | natural-prompt arms |

**Result for every candidate: INSTALLED = no** (except the already-adopted Ponytail pair and Superpowers 7.0.0).
**LOADABLE** was verified for the benchmarked skills only, under Claude Code, project scope, explicit "use the X skill" prompt.
**ACTUALLY USED (natural prompt): 0 of 4.** With frontend-design, design-taste-frontend, ui-ux-pro-max and emil-design-eng all installed and a plain "redesign this page" prompt, the model never called the Skill tool (`ui__natural`; an earlier run with one skill mis-installed also made no call). An installed description list does not select a skill; explicit routing is required.

Host compatibility column: **CC** Claude Code (tested, project scope) · **CX** Codex · **OC** OpenCode · **HM** Hermes · **AG** Antigravity. CX/OC/HM are *format-compatible by inference* (same SKILL.md convention as the 91 Orchestra links and the vendored Ponytail) and **NOT TESTED** for these candidates. **AG: UNVERIFIED** (no Antigravity host to test against).
