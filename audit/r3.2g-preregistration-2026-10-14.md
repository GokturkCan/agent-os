# R3.2G pre-registration — lightweight Laya pipeline + ecosystem modules (written before any R3.2G result)

R3.2C and R3.2F are CLOSED and immutable. Gates G1–G7 are used exactly as defined in Phase 2A §6. Production defaults stay
`systemone.backend: "null"` / `fastgate.model: null`. Laya runtime reused unchanged: `aac6fef/laya-multilingual-mlx`@f2b4faf5,
laya-mlx 0.4.0 (backend `laya-mlx`, worker `laya_worker.py` untouched = the control). No new model downloads.

## 1. Pipeline under test (`agentos/systemone_pipeline.py`, a `SystemOneBackend` wrapping the existing `laya-mlx` adapter backend)
Hermes → C0 deterministic policy (unchanged) → **prepare** → Laya → **validate** → optional **verify** → accept / abstain / escalate.
Independent switches:
* `neutral` (on/off): each option id is replaced by a per-request alias `cand_<4 hex>` derived from a hash of
  (request content, option) — not from list position; whole-word occurrences of the original ids inside `state` strings are
  rewritten with the same mapping (preserves e.g. "review the change written by X"); option metadata is carried over unchanged;
  answers are mapped back; an answer that does not map back to an eligible id escalates `ineligible-choice`.
* `strategy`:
  * `choice` — one Laya choice question (= vanilla behaviour).
  * `per-option` — each option scored independently against the fixed "none fits" anchor (the existing abstain text) in its
    own 2-way Laya call: score(o) = P(o) (= reported confidence if o is chosen, else 1 − confidence). Pick argmax. If
    `allow_abstain` and max score < 0.5 (every option loses to "none fits") → escalate `backend-abstained`. N calls.
  * `consistency` — the `choice` question asked in 2 orders (given, reversed) plus a rotation by one when ≥ 3 options; all agree →
    accept (raw confidence = minimum); any disagreement → escalate `low-confidence`. 2–3 calls.
* Validation (always on): typed reply checks, eligibility (re-checked by `system_one()` as before), alias round-trip, any error in
  any sub-call → escalation with that reason (fail-closed), provenance trace per decision (strategy, neutral, calls, sub-choices).
* Single option: passed to the inner backend exactly as the vanilla path does. Zero options never reach the pipeline.
* No threshold other than the structural 0.5 of the 2-way anchor comparison; no prompt text changes; no tuning on held-out data.

## 3. Confidence / calibration (offline only, `agentos/systemone_calibration.py`)
Top-choice raw confidence vs `correct`: reliability bins, ECE (10 equal-width bins), Brier, AUROC, coverage–accuracy curve;
isotonic (PAV) and Platt fitted on dev records only, applied unchanged to v2 records. Reported as analysis; never used to gate,
never `kind="calibrated"` in any runtime path.

## 4. Task-specific modules (separate acceptance suites; none wired into routing or hooks; all opt-in, offline)
* WakeGate (`agentos/wakegate.py`): deterministic must-wake rules (high risk, approval required, security/credential markers,
  errors/failures, explicit user message, deadline) → WAKE without model; unchanged observation hash → DEFER without model; else
  Laya 3-way {wake_local_reasoning, wake_cloud_candidate, defer_no_change}; any failure/abstain/escalation → WAKE (local);
  `max_skips` consecutive defers → WAKE. Acceptance: missed-important (false-negative) = 0 on the suite; report unnecessary
  wakes and avoided calls. Rules-only ablation reported alongside.
* ContextGate (`agentos/contextgate.py`): derived view only; originals stored content-addressed; deterministic KEEP for user/
  security/approval text, paths, errors/codes, CLI args, stack traces, JSON/YAML/XML/diff, citations, recent N items; Laya
  KEEP/TRUNCATE/DROP only for unprotected tool results, on a bounded head (≤ 600 chars); every drop/truncation leaves a recovery
  marker. Acceptance: essential-fact false-drop rate = 0, recovery round-trip exact; report token reduction. Deterministic-only
  ablation reported alongside (model OFF).
* Tool-result pruner (`agentos/toolpruner.py`): pass-through under a size floor; deterministic noise removal (ANSI, progress bars,
  repeated lines); protected error/warning/path/structured lines; optional Laya keep/drop per unprotected chunk; original kept.
  Acceptance: essential-line loss = 0; report token savings with model OFF and ON.
* Decision→rule cache (`agentos/rulecache.py`): only explicitly human-approved rules apply; scoped key (task class, option set,
  capabilities, risk, option metadata hash, config hash); proposed rules never apply; invalidated on any key/config change.
* Compat (`agentos/systemone_compat.py`): TypeSafe-shaped `{state, questions}` ⇄ `SystemOneRequest/Response` mapping; criteria
  keys must be a subset of a caller-supplied policy-eligible set; function + CLI only, no daemon, no new dependency.
Module suites are synthetic, author-written, labelled from explicit rules before running; they measure the module, not
worker-routing accuracy, and are reported separately.

## 5. Evaluation dataset v2 (new file, author → reviewer → freeze before ANY v2 scoring)
`evals/data/systemone-heldout-v2.yaml`, target 128–160 cases, EN/TR balanced, same schema/validator. Families: multiple eligible
workers by role/capability, single/no-option, label swaps (misleading ids), description swaps, order permutations (all orders
scored), counter-prior, insufficient information/escalation, risk-sensitive routing, misleading labels, dynamic availability /
resource facts, realistic agent operations, error/timeout/invalid-option cases. Gold from config facts only (cited `facts`).
Author: this session. Reviewer: a separate fresh-context model pass that labels a blinded copy (no gold, no rationale) and whose
disagreements are adjudicated against config facts; plus deterministic label tests. **No human reviewer** — disclosed.
After freeze: sha256 recorded in this directory and committed before scoring; no edits after scoring.
v2 runs (sequentially, one memory-heavy job at a time): vanilla Laya (A), the dev-selected config C, Open-Jev-2B (D, existing
runtime, bf16/MPS), baselines (first/last/label-prior/random), null. G1–G7 applied unchanged (G5 vs v2 label-prior).
Per language and per category reported. v1 held-out may be re-run for continuity only and is labelled non-pristine.
